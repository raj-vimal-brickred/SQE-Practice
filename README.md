# SQE Practice

## Overview

SQE Practice is a local SQE-style telemetry monitoring application built using .NET.

The purpose of the project is to understand how a standing-query telemetry processing system works.

The application:

1. Receives telemetry events.
2. Checks the events against configured standing queries.
3. Processes matching events inside a configured time window.
4. Groups events using dimensions.
5. Generates metrics.
6. Evaluates alert thresholds.
7. Stores events, metrics, and alerts in SQL Server.
8. Uses OpenTelemetry to observe the SQE processing pipeline.

This project is a learning and reproduction application. It is not the actual Geneva SQE service.

## EventIngestionService

EventIngestionService coordinates event processing.

Flow:

Event

    ↓

    ↓

# Standing Queries

Standing queries define which telemetry events the system continuously monitors.

The queries are stored in:

Queries/queries.json

Example:

{
  "queries": [
    {
      "name": "OrderFailureCount",
      "eventName": "OrderFailed",
      "aggregation": "count",
      "windowSeconds": 60,
      "dimensions": [
        "service",
        "region"
      ],
      "alert": {
        "operator": "gte",
        "threshold": 3
      }
    }
  ]
}


## QueryLoader

QueryLoader reads queries.json and converts the query configuration into StandingQuery objects.


## StandingQueryEngine

StandingQueryEngine receives a telemetry event and compares it with all configured standing queries.

Example:

Incoming Event:

OrderFailed

Configured Query:

OrderFailed

Result:

MATCH


A different event:

OrderCreated

does not match:

OrderFailed

Result:

NO MATCH


# Time Window

Standing queries operate over a configured time period.

Example:

windowSeconds = 60

Events:

10:00:05 OrderFailed

10:00:20 OrderFailed

10:00:40 OrderFailed

The query evaluates events that belong to the configured window.


# Dimensions

Dimensions split metrics into different groups.

Example dimensions:

service
region

Events:

OrderFailed | OrderService | East

OrderFailed | OrderService | East

OrderFailed | OrderService | West


Generated metric groups:

OrderService + East = 2

OrderService + West = 1


# Aggregation

AggregationEngine converts matching telemetry events into numerical metrics.

The initial aggregation implemented in the project is:

Count

Example:

OrderFailed
OrderFailed
OrderFailed

Result:

OrderFailureCount = 3


Additional aggregation types can be implemented, such as:

Sum
Average
Minimum
Maximum
Distinct Count


# Metrics

A metric represents the result of a standing query.

Example:

Metric Name:

OrderFailureCount

Value:

3

Dimensions:

Service = OrderService
Region = East


Metrics are available through:

GET /api/metrics


# Alerts

AlertEngine evaluates generated metrics against configured thresholds.

Example rule:

OrderFailureCount >= 3


If:

OrderFailureCount = 1

No alert is generated.


If:

OrderFailureCount = 3

The condition becomes:

3 >= 3

An alert is generated.


Alerts are available through:

GET /api/alerts

# OpenTelemetry

OpenTelemetry is added to observe how the SQE reproduction application itself behaves.

This is separate from the business metrics generated by the StandingQueryEngine.


For example:

OrderFailureCount = 5

is a metric generated by the SQE logic.


An OpenTelemetry metric such as:

sqe.events.received

describes the operation of the SQE application itself.


# OpenTelemetry Tracing

The application uses an ActivitySource.

Example:

ActivitySource

    ↓

Event Ingestion

    ↓

Standing Query Processing

    ↓

Query Match

    ↓

Aggregation

    ↓

Metric Generation

    ↓

Alert Evaluation

    ↓

SQL Server


The ActivitySource must be registered with OpenTelemetry using:

.AddSource("SQE_Practice")


# OpenTelemetry Metrics

The application uses a Meter for operational metrics.

Example metrics:

sqe.events.received

sqe.events.matched

sqe.events.unmatched

sqe.metrics.generated

sqe.alerts.triggered

sqe.processing.duration


The Meter must be registered using:

.AddMeter("SQE_Practice")


# OpenTelemetry Console Exporter

For the reproduction exercise, traces and metrics are exported to the console.

OpenTelemetry configuration contains:

.AddOpenTelemetry()

Tracing:

.AddSource("SQE_Practice")

Metrics:

.AddMeter("SQE_Practice")

Exporter:

.AddConsoleExporter()


The console output is used to verify that spans and metrics are being produced.
